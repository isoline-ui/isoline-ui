## A complete form

Keep field and submit state together. Pass your own asynchronous save function; it can call a local database, an API, or your existing store.

```tsx title="ProfileForm.tsx"
import { useState } from 'react';
import { View } from 'react-native';
import { Button, LoadingIndicator, Text, TextField } from '@isoline-ui/react-native';
type Props = { onSave: (name: string) => Promise<void> };
export function ProfileForm({ onSave }: Props) {
  const [name, setName] = useState('');
  const [error, setError] = useState<string | null>(null);
  const [saving, setSaving] = useState(false);
  const [saved, setSaved] = useState(false);
  async function submit() {
    if (saving) return;
    const value = name.trim();
    if (!value) {
      setError('Enter your name.');
      return;
    }
    setError(null);
    setSaved(false);
    setSaving(true);
    try {
      await onSave(value);
      setSaved(true);
    } catch {
      setError('Could not save. Please try again.');
    } finally {
      setSaving(false);
    }
  }
  return (
    <View className="gap-5 p-6">
      <Text variant="title">Your profile</Text>
      <TextField
        label="Your name"
        value={name}
        onChangeText={(value) => {
          setName(value);
          setError(null);
          setSaved(false);
        }}
        error={error}
        editable={!saving}
        notchClassName="bg-background"
        autoCapitalize="words"
        returnKeyType="done"
        onSubmitEditing={() => void submit()}
      />
      <Button
        label={saving ? 'Saving…' : 'Save changes'}
        disabled={saving}
        accessibilityState={{ busy: saving, disabled: saving }}
        onPress={() => void submit()}
      />
      {saving && <LoadingIndicator size={28} />}
      {saved && <Text accessibilityLiveRegion="polite">Your profile is saved.</Text>}
    </View>
  );
}
```

## Connect it to your app

Render this below `IsolineProvider`, for example `<ProfileForm onSave={saveProfile} />`, where `saveProfile` is your application's persistence function.

## Validation that helps

Show a useful error near the input. The example requires a non-empty name. For several fields, keep errors by field so each message appears next to the value that needs attention. Do not clear the user's work after a failed request.

Use `keyboardType`, `autoCapitalize`, `textContentType`, `secureTextEntry`, and `returnKeyType` on `TextField` where appropriate. For several inputs, use refs and `onSubmitEditing` to move focus forward.

## While saving

Disable repeat submission, make the field non-editable when needed, and show a clear busy label. Keep the main action in place so the layout does not jump. In a dialog, close only after success and decide how to handle dismissal while saving.

For longer forms, use a scrollable screen with safe-area and keyboard handling. Test the last input and action with the keyboard open, large text, and translated labels. For a short modal form, see [Overlays with forms](/en/docs/guides/overlays).
