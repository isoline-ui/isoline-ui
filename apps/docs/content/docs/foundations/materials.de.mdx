## Adapter einrichten

Das UI-Paket bleibt unabhängig von Expo. Übergib die optionalen Adapter aus `@isoline-ui/native` an den Provider. Ohne Adapter funktionieren die Controls mit soliden Theme-Flächen. `surface` bleibt als älterer Alias für `surfaceComponent` verfügbar.

```tsx title="MaterialRoot.tsx"
import type { ReactNode } from 'react';
import { SafeAreaProvider } from 'react-native-safe-area-context';
import { IsolineProvider, themes } from '@isoline-ui/react-native';
import { MaterialSurface, MaterialGroup } from '@isoline-ui/native';

export function MaterialRoot({ children }: { children: ReactNode }) {
  return (
    <SafeAreaProvider>
      <IsolineProvider
        theme={themes.violet.light}
        surfaceComponent={MaterialSurface}
        surfaceGroupComponent={MaterialGroup}
      >
        {children}
      </IsolineProvider>
    </SafeAreaProvider>
  );
}
```

## Gemeinsamer Materialvertrag

| Prop            | Bedeutung                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| `material`      | `auto`, `glass` oder `solid`. Native Geräte folgen ihrer Plattform; Android-Controls bleiben solide. |
| `glassStyle`    | `regular` oder `clear`. `regular` bleibt der Standard.                                               |
| `tintColor`     | Optionale Tönung der Glasfläche. Eine deckende Farbe kann den Hintergrund verdecken.                 |
| `fallbackColor` | Farbe der soliden Alternative.                                                                       |
| `interactive`   | Native Materialinteraktion; ersetzt keinen `onPress`-Handler.                                        |

Controls wie `Button`, `IconButton`, `FloatingActionButton`, `FabMenu`, `SplitButton`, `SearchField` und `ButtonGroup` behalten standardmäßig ihre solide Darstellung. Mit `material="auto"` oder `material="glass"` verwenden passende iOS-Flächen Glas. `Toolbar` (beide APIs), `NavigationBar`, `TopBar`, `TabBar`, `Popover` und `ContextMenu` fragen standardmäßig das automatische Material an. `SelectField` hält seinen Trigger solide und verwendet für das Menü `menuMaterial="auto"`.

`Dialog`, `BottomSheet`, `PanelSheet`, `MenuSheet` und `Snackbar` bleiben standardmäßig solide; ihre Materialwahl ist explizit. Formulare, Einstellungen, längere Texte und leere Zustände benötigen keine pauschale Glasfläche. Für Menüs von `SplitButton` steuert `menuMaterial` die überlagerte Fläche unabhängig vom Button.


## Prüfung der Overlays und schwebenden Controls

Die [Materialvergleichs-Demo](/de/docs/components/overlay-materials) zeigt die neuen Sheets und schwebenden Rückmeldungen über einem farbigen Hintergrund. Passwörter haben einen [eigenen Live-Leitfaden](/de/docs/components/password-input).

| Komponenten | Materialfläche und Standard |
| --- | --- |
| `DatePickerSheet`, `TimePickerSheet`, `ColorPickerSheet` | Vollständige `MaterialOptions` am Sheet; aus Kompatibilität standardmäßig `solid`. `material="auto"` aktiviert iOS-Glas. |
| `DateField`, `TimeField` | Reichen diese Optionen an ihr Sheet weiter. Auslöser und Formularinhalt bleiben solide. |
| `SelectField`, `SettingsSelectRow`, `SplitButton`, verankertes `FabMenu` | `menuMaterial="auto"` steuert das Menü unabhängig vom soliden Auslöser. Stil, Tönung und Alternative werden ebenfalls weitergereicht. |
| `Popover`, `ContextMenu`, Toolbar-, Navigations- und Tab-Leisten | Standardmäßig automatisches iOS-Material. |
| `Dialog`, `BottomSheet`, `PanelSheet`, `MenuSheet` | Materialoptionen verfügbar; `solid` bleibt Standard. Reguläres Glas eignet sich für kurze, lesbare Formulare. |
| `UndoBar`, `Snackbar`, `JumpToTopPill`, `ActionChip`, schwebende Buttons | Über Inhalten optional Glas verwenden; standardmäßig `solid`. |
| `ZoomableImage` | Die schwebende Zoom-Leiste verwendet standardmäßig `auto`. Material, Stil, Tönung und Alternative gelten für Controls, niemals für das Bild. |
| Passwort-/Text-/Betragsfelder, Inline-Kalender, Banner, Einstellungszeilen, Wischaktionen | Solide Inhalte, keine Glasflächen. Das umgebende Sheet oder Menü kann Glas verwenden. |

`FabMenu` behält seine bisherige solide native Erweiterung im entsprechenden Legacy-Modus; `menuMaterial` konfiguriert die verankerte Menüdarstellung. Natives Glas benötigt den Adapter und ein unterstütztes iOS-Gerät. Web-Blur ist eine CSS-Annäherung; Android, reduzierte Transparenz und nicht unterstützte Browser verwenden solide Alternativen. Bei `solid` als Standard wird Glas gezielt aktiviert, nicht pauschal auf alle Komponenten angewendet.

## Zustände und Bewegung

Glasflächen liegen außerhalb des Press-Opacity-Feedbacks ihrer Kinder. Deaktivierte Controls bleiben nicht bedienbar. Die Tab-Leiste animiert ihre Auswahl auf nativen Geräten; Tastatur, ausgewählte und deaktivierte Zustände sind im Web vorhanden. Die Toolbar blendet das Material beim automatischen Verstecken nicht über Opacity aus, sondern bewegt es aus dem Bild.

`SurfaceGroup` mit `gap` verbindet Layoutänderungen mit einem nativen `GlassContainer`; reduzierte Bewegung überspringt die Übergänge. Der Browser animiert Abstände und zeigt separate CSS-Flächen. Er simuliert weder native Verschmelzung noch Brechung. SwiftUI-Matched-Geometry und anwendungsbezogene Navigation gehören nicht zu diesem React-Native-Vertrag.

## Plattformen und Alternativen

Natives Liquid Glass benötigt iOS 26+, verfügbare APIs und deaktivierte reduzierte Transparenz. Die Adapter verwenden sonst solide Flächen. Im Browser kommen CSS-Glas und solide Alternativen bei fehlenden Filtern, erzwungenen Farben oder gemeldeter reduzierter Transparenz zum Einsatz. Zeige die Beispiele über abwechslungsreichem Inhalt; passe nicht die globale Opacity des Glases an.

Die Browser-Vorschauen ersetzen keine Tests auf iOS-Geräten. Prüfe Hell/Dunkel, VoiceOver, größere Schrift, reduzierte Bewegung, reduzierte Transparenz und Tastaturverhalten in deinen tatsächlichen Bildschirmen.
