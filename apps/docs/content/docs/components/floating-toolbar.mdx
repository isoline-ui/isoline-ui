`Toolbar` is the shared surface for the floating action bar. It arranges your `Button` and `IconButton` controls; you choose the actions and place it above your screen content. In the preview, scroll the collection, try New and More, switch iOS/Android, or request a solid surface.

The colored motifs in the collection actually sit behind the floating toolbar. Scroll them underneath it and use Solid surface to compare the same content with and without glass.

## Float above the content

Keep the toolbar outside the `ScrollView`, position it above the bottom safe area, and reserve enough bottom padding in the scrolling content so the last item remains reachable.

```tsx title="CollectionScreen.tsx"
import { useState } from 'react';
import { ScrollView, View } from 'react-native';
import { SafeAreaProvider, useSafeAreaInsets } from 'react-native-safe-area-context';
import {
  BackIcon,
  Button,
  IconButton,
  IsolineProvider,
  Text,
  Toolbar,
  themes,
  useThemeColors,
} from '@isoline-ui/react-native';
import { MaterialSurface } from '@isoline-ui/native';

export function CollectionScreen() {
  return (
    <SafeAreaProvider>
      <IsolineProvider theme={themes.violet.light} surfaceComponent={MaterialSurface}>
        <CollectionContent />
      </IsolineProvider>
    </SafeAreaProvider>
  );
}

function CollectionContent() {
  const insets = useSafeAreaInsets();
  const colors = useThemeColors();
  const [status, setStatus] = useState('Your collection');
  return (
    <View style={{ flex: 1, backgroundColor: colors.surface }}>
      <ScrollView
        contentContainerStyle={{
          padding: 16,
          paddingTop: insets.top + 16,
          paddingBottom: insets.bottom + 104,
        }}
      >
        <Text variant="title">{status}</Text>
        {Array.from({ length: 12 }, (_, index) => (
          <View key={index} style={{ paddingVertical: 24 }}>
            <Text>Project {index + 1}</Text>
          </View>
        ))}
      </ScrollView>
      <Toolbar
        style={{
          position: 'absolute',
          left: insets.left + 16,
          right: insets.right + 16,
          bottom: insets.bottom + 16,
        }}
      >
        <IconButton
          icon={BackIcon}
          accessibilityLabel="Go back"
          onPress={() => setStatus('Back selected')}
        />
        <Button label="New" size="s" onPress={() => setStatus('Item added')} />
        <Button
          label="More"
          size="s"
          variant="ghost"
          onPress={() => setStatus('More selected')}
        />
      </Toolbar>
    </View>
  );
}
```

In an app that already provides `SafeAreaProvider` and `IsolineProvider`, reuse them instead of adding another app root. Connect the actions to your own navigation and screen state. For overflow actions use [MenuSheet](/en/docs/components/menu-sheet); its modal belongs alongside the screen, outside the scrolling content.

## iOS, Android and web

On iOS, the toolbar uses a rounded capsule. With `surfaceComponent={MaterialSurface}`, supported iOS 26+ devices use native Liquid Glass. Older devices and Reduce Transparency use a solid theme surface. Android uses a solid Material surface with its own geometry. Without a surface adapter, the toolbar remains usable as a solid themed surface.

The browser preview renders the same `Toolbar` through React Native Web. iOS-style glass uses a CSS approximation with a solid fallback for unsupported backdrop filters, reduced transparency or forced colors. `material="solid"` explicitly selects the solid alternative. See [Liquid Glass](/en/docs/native/liquid-glass) for setup and availability.

## Choose the actions

Keep the main action visible and move less frequent actions into a menu. Give icon-only controls meaningful accessibility labels. Do not reduce the opacity of the toolbar or its ancestors to indicate a pressed action; let the child controls handle feedback. Avoid opaque backgrounds that hide the glass material.

`Toolbar` supplies the surface and horizontal arrangement. Positioning, safe-area insets, keyboard avoidance, selection state, navigation and scroll-driven visibility remain screen responsibilities. It does not automatically attach itself to the viewport or recreate app-specific behavior.

## Props

| Prop        | Type / default                         | Purpose                                                  |
| ----------- | -------------------------------------- | -------------------------------------------------------- |
| `children`  | `ReactNode`                            | Actions such as `Button` and `IconButton`.               |
| `material`  | `auto / glass / solid · default: auto` | Select the iOS material preference; Android stays solid. |
| `style`     | `StyleProp<ViewStyle>`                 | Position the toolbar and adjust layout.                  |
| `className` | `string`                               | Additional NativeWind styling.                           |
| View props  | `ViewProps`                            | Accessibility and other container properties.            |

For a title with leading/trailing navigation controls, use `NavigationBar`, described in [platforms and navigation](/en/docs/foundations/platforms).
