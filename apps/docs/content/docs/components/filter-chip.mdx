Use a chip for a filter that can be on or off. Multiple chips can be selected independently when your app stores multiple values.

## Toggle a filter

```tsx
import { useState } from 'react';
import { FilterChip } from '@isoline-ui/react-native';
export function UnreadFilter() {
  const [selected, setSelected] = useState(false);
  return (
    <FilterChip
      label="Unread"
      selected={selected}
      onPress={() => setSelected((value) => !value)}
    />
  );
}
```

## Match the surrounding surface

The unselected chip has its own fill. Set `surface="popover"` inside a shared dialog or sheet, or `surface="surfaceContainerHigh"` when it sits on that tone. Use the default `background` on a normal screen.

## Opening a choice

A chip can also open a sheet instead of toggling directly. Use a trailing chevron icon and set `selected` according to whether a filter is active. Provide the sheet and its state in your app. Do not hide the only way to change a filter behind `onLongPress`.

This component has no `disabled` or `className` prop in the current release. Use the documented props and place it in a styled parent view when needed.

## iOS capsules

On iOS, filter choices use a capsule with a minimum 44-point height, a neutral
system-role fill and the primary tint when selected. Leading/trailing icons,
long press, selection accessibility and labels keep the same API. Android keeps
its stable fill/border layers and expressive motion. Do not disable text scaling
for filters; verify large labels inside horizontal scroll containers.

The shared iOS control owns its spacing, label and trailing-icon sizes and
pressed-opacity feedback. Selection feedback uses the provider's haptic callback:
`haptic` defaults to enabled on iOS and disabled elsewhere. Pass `haptic={false}`
to suppress it or `haptic={true}` to opt in on another platform. Long press stays
a separate action. Theme colors, labels and selection remain consumer inputs.
