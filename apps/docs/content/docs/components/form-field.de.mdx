Beschriftungen, Pflichtmarkierungen, Hilfetexte und Fehler für Felder vereinheitlichen.

## Verwendung und Zustände

Für Controls ohne eigene Beschriftung/Fehlerdarstellung. `requiredLabel` ist sichtbarer lokalisierter Text, keine Validierungsregel. Beschriftung und Fehler/Hinweis auch dem Control als barrierefreien Namen/Hinweis mitgeben; der Wrapper klont keine Kinder und erzeugt keine native Label-Zuordnung. Fehler haben Vorrang vor Hinweisen und werden höflich angekündigt. Validierung und Absenden bleiben in der App.

## Vollständiges Beispiel

Die Demo und dieses Beispiel verwenden dieselbe Implementierung. In einer bestehenden App verwende den vorhandenen Provider weiter.

```tsx title="FormfieldExample.tsx"
import * as React from 'react';
import { View, ScrollView } from 'react-native';
import { SafeAreaProvider } from 'react-native-safe-area-context';
import { GestureHandlerRootView } from 'react-native-gesture-handler';
import * as UI from '@isoline-ui/react-native';

type StoryProps = { de?: boolean };

function FormFieldExample({ de = false }: StoryProps) {
  const [checked, setChecked] = React.useState(false);
  const label = de ? 'Einwilligung' : 'Consent';
  const hint = de ? 'Du kannst die Auswahl ändern.' : 'You can change this choice.';
  return (
    <UI.FormField
      label={label}
      requiredLabel={de ? '(erforderlich)' : '(required)'}
      hint={hint}
    >
      <UI.Checkbox
        checked={checked}
        onCheckedChange={setChecked}
        accessibilityLabel={`${label}, ${hint}`}
        label={de ? 'Ich stimme zu' : 'I agree'}
      />
    </UI.FormField>
  );
}

export function Example() {
  return (
    <GestureHandlerRootView style={{ flex: 1 }}>
      <SafeAreaProvider>
        <UI.IsolineProvider theme={UI.themes.violet.light}>
          <FormFieldExample de={true} />
        </UI.IsolineProvider>
      </SafeAreaProvider>
    </GestureHandlerRootView>
  );
}
```
